# AI-Co Project Context

AI-Co is a Sneedworks project: an independent C-based systems programming language optimized primarily for AI coding agents.

## Authority

For consequential work, apply current sources in this order:

1. Marcel's explicit current direction.
2. `../../governance/CONSTITUTION.md`.
3. `../../governance/OPERATIONS_MANUAL.md`.
4. Accepted Sneedworks ADRs and role specifications.

Conflicts and Low requirements or architecture confidence block implementation and must be escalated to the proper owner.

## Current architecture

- Stage-0 compiler: conservative C17.
- First host and target: native Windows x86-64.
- Initial backend: deterministic project-owned x86-64 COFF object emission; external MSVC or LLD linking is temporarily permitted.
- Compiler stages: source loading/UTF-8 validation, deterministic lexer, parser, typed representation, resolution/type checking, semantic validation, canonical IR, x86-64 backend, COFF emission, structured diagnostics.
- Canonical diagnostics: versioned JSON Lines; human text is a secondary rendering.
- Bootstrap milestone: Stage 0 builds Stage 1, Stage 1 builds Stage 2, Stage 1 and Stage 2 outputs are byte-identical after only explicitly specified normalization, and both pass conformance and diagnostic suites.
- Compiler core: no LLVM library, parser generator, package manager, network service, or third-party runtime dependency.

Read `PROJECT_CHARTER.md`, `docs/adr/ADR-001-bootstrap-compiler-and-initial-target.md`, and `docs/adr/ADR-002-minimal-core-language-semantics.md` before planning, implementing, or reviewing language behavior.

## Work boundaries

- Main Designer owns architecture and language-design decisions.
- Planner owns the normative specification, milestones, and implementation-ready work packages.
- Coordinator owns routine board routing and completion gates.
- Researcher owns external/current evidence.
- Specialists implement only from accepted, implementation-ready work.
- Reviewer independently assesses artifacts and evidence.
- Historian maintains project record freshness and supersession.

Do not let implementation convenience define syntax, semantics, diagnostic contracts, or bootstrap acceptance. Do not implement production code while the relevant specification or architecture confidence is Low.

## Environment constraints

The evidence baseline is `research/ENVIRONMENT_BASELINE_2026-08-08.md`.

- Build output, caches, and temporary compiler artifacts belong on E:, not the critically constrained C: drive.
- Tool entry points must initialize the Visual Studio x64 developer environment or use explicit paths.
- Never invoke ambiguous bare `link` from Git Bash; Git's coreutils executable shadows the Microsoft linker.
- Use `python`, not the Windows Store `python3` alias, for authorized support scripts.
- Secrets never enter this repository.
