## 1. Objective

Turn the adopted S2a-IR stopgap into a bounded, implementation-ready verification package that runs **after WP-M0-16c2 (t_07aacd82) completes** and **before codegen (WP-M0-17) consumes the IR**: a set of minimal AI-Co programs, one feature each, focused on the trickiest builder lowerings, verified at the IR boundary with an **independent, hand-computed oracle** (per IR-CONTRACT-2026-08-12) plus the accepted 16b2 machinery (`ir_core_verify` AIC-I0501, deterministic dump, dump/parse/re-dump byte-identity). The tranche's purpose is to surface wrong-but-consistent (G2) builder lowerings at the cheapest point — while the IR builder is still the only consumer — and to **gate WP-M0-17 and the 16-section push wave** structurally (design record §S2a-IR "Placement").

Behavioral dual-reference (S2a refinement R1, executable comparison) is **explicitly out of scope** — no executables exist until post-M0; this tranche verifies IR construction only.

## 2. Scope (IR-boundary, not behavioral)

Minimal AI-Co programs, one feature each, targeting the trickiest lowerings named in the design record §S2a-IR:

1. **Compound assignment** — destination-location order (spec §10.4 assignment order; dest location evaluated before source), alias-through-global location operands (the 16c1c remediation rounds: `*gp += bump()`, `a[giu] += bump()`, `*getp() += bump()`). Lowered shape: dest-location + source + op + store.
2. **Repetition form `[e; N]`** — IRC-N1 evaluate-exactly-once (including one evaluation when `N == 0`); lowered via single evaluation + repeated stores; no N-times re-evaluation.
3. **Cast/wrap matrix** — IR_CAST vs IR_WRAP selection per the §11.2 matrix (checked vs wrapping/truncating), incl. signedness, narrowing, bool↔int, enum, pointer↔int, `str`↔`u8[]` reinterpret/UTF-8 validation obligations, and the constant-rejected (pre-IR) counterparts where exercised.
4. **Pointer arithmetic / value categories** — IR_PTR_ADD / IR_PTR_SUB / IR_PTR_DIFF lowering (scaled offsets, checked arithmetic, trap obligations), value categories §5.4 (scalar direct vs composite address-resident; lvalue rules; str/slice indexing yields a value address, never an lvalue; no addressable const).
5. **Struct/array literal lowering** — IR_ZERO + field/element stores; composite padding zeroing obligations; composite initializers address-resident.
6. **Trap obligations** — every lowered node carries its enforcement (trap code + span/facts per contract §5.3): overflow AIC-R0802, div-zero AIC-R0803, shift AIC-R0804, bool-load AIC-R0805, UTF-8 AIC-R0806, bounds AIC-R0807/R0808, null deref AIC-R0809, ptr-diff AIC-R0810/R0816.

**Oracle discipline (G4 protection):** each program's expected IR is **hand-computed from IR-CONTRACT-2026-08-12** (node kinds, canonical construction order, operand ids, canonical constant forms, spans, trap codes) and authored as an embedded string constant **before/independently of** running the builder. Builder output must match the oracle byte-for-byte via `ir_dump_write`. No expected IR may be generated by running the builder and copying its output (that would re-encode the implementation's blind spot).

**Boundary values mandatory (S2a R2):** each feature's cases include edge values where the feature has numeric bounds — 0, INT32_MIN/MAX, -1, 64-bit boundaries, overflow-into-trap, negative immediates, `N == 0`, max shift counts, etc. Wrong codegen paths often produce correct answers for typical inputs; boundary values are what turn "wrong but observably correct" into "wrong and caught".

**Composition subset (small):** 2–3 programs deliberately combining 2–3 features (e.g., struct literal inside a loop with checked arithmetic; compound assignment through a global pointer plus wrap) to catch interaction bugs. Localize to the intersection of involved code paths.

## 7. Acceptance criteria

1. **Coverage:** every feature area in §2 (1)–(6) has ≥ 1 minimal micro-program with an embedded, hand-computed expected-IR oracle authored from IR-CONTRACT (oracle provenance recorded per case; no oracle copied from builder output).
2. **Compound-assignment correctness:** cases for destination-location order and alias-through-global reproduce the exact failed-review shapes (`*gp += bump()`, `a[giu] += bump()`, `*getp() += bump()`) and their lowered IR matches the oracle (dest-location operands before source; single dest-location evaluation).
3. **Repetition form:** `[e; N]` cases prove evaluate-exactly-once in the IR (single source evaluation + repeated stores), including `N == 0` (one evaluation, zero stores).
4. **Cast/wrap:** matrix cases select IR_CAST vs IR_WRAP per §11.2; boundary values (narrowing, signedness edges, bool↔int, enum, pointer↔int, str↔u8[]) present; trap/validation obligations carried on the nodes.
5. **Pointer arithmetic / value categories:** PTR_ADD/SUB/DIFF scaled-offset lowering with AIC-R0816/R0810 obligations; no non-lvalue store, no addressable const, str/slice indexing yields value address (never lvalue), composite values address-resident — all confirmed in the dumps.
6. **Struct/array literals:** lowered to IR_ZERO + field/element stores with padding-zeroing; composite initializers address-resident per §5.4.
7. **Verification per case:** pipeline clean → `ir_builder_build` returns IR_BUILDER_OK → `ir_core_verify` returns IR_OK with 0 AIC-I0501 records → `ir_dump_write` output is byte-identical to the embedded oracle → dump/parse/re-dump byte-identical (invariant 12).
8. **Exclusions honored:** no modification of any read-only file (§3); no source changes outside the two owned files; no spec/ADR/contract/governance edits; no push.
9. **Completion protocol:** handoff evidence posted as a comment, then `kanban_block(reason='review-required: <one-line summary>')` — never self-complete (manifest §1 rule 8).

## 9. Risks and escalation

- **Oracle drift:** hand-computed dumps diverging from the builder's canonical dump format → remediation rounds (precedent: 16c1c three rounds). Mitigation: author oracles from the contract §11 dump-content/canonical-form spec; keep programs minimal.
- **Boundary-value gaps:** cases using only typical values would weaken R2. Mitigation: explicit boundary note per case in the completion report.
- **Builder defect surfaced:** if a case fails, the tranche **reports** the defect with the failing dump diff — it does **not** fix 16c-owned builder code (read-only; fixing is a remediation card routed by the Coordinator to the owning package). A surfaced defect is a success of the stopgap, not a package failure; escalate per OM §6.1.
- **Escalation:** IR boundary conflict (contract interpretation vs builder behavior) → **Main Designer**. Anything requiring a new IR node or contract change → Main Designer (closed set, contract §5.5). File-ownership ambiguity → Planner via Coordinator.
